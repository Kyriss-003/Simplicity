## 2. Folder Persistence — Data Layer
- `src/db/schema.ts`: `folders` table already exists (`id TEXT PK, uuid, label, parent_id, is_deleted, created_at, updated_at`) — no change needed. Add a `FolderRow` interface + `Folder` app model (camelCase, boolean `isDeleted`).
- `src/db/NoteRepository.ts` (or new `FolderRepository` section inside it, keeping the existing dual native/web backend pattern):
  - `getAllFolders()` (excludes `is_deleted`, ensures root `main`/`Main` exists on first read — seed if table empty)
  - `createFolder(label, parentId)`, `renameFolder(id, label)`, `moveFolder(id, newParentId)` (cycle check), `duplicateFolder(id)` (deep clone with new uuids, `- copy` labels), `softDeleteFolder(id)` (cascade soft-delete descendant folders + contained notes)
  - Web/localStorage backend mirrors the same operations

## 3. Store Layer (`src/store/useNoteStore.ts`)
- Add `folders: Folder[]`, folder CRUD actions delegating to the repository (same pattern as notes), each re-fetching/patching `folders`.
- `selectedFolderId: string | null` (default `'main'`); `setSelectedFolder(id)` reloads notes for that folder (fix current behavior where caller must re-call `getAllNotes`).
- Folder action callbacks take explicit target IDs (`createNoteInFolder(folderId)`, `moveNote(noteId, folderId)`, `moveFolder(folderId, targetParentId)`, etc.) so context-menu actions on unselected rows never disturb the active view.
